# The source portal to export

The migration example matches an email/password portal generated by Lovable's AI. The source uses TanStack Start and native Lovable Cloud.

The person creates two invented accounts through the app: `barbara@example.com` and `michael@example.com`. Keep the fixture password in a private file.

Each account owns one invoice record, one private text document and one PENDING record-count job. The [migration guide](../../../docs/app-platform-migrations/from-lovable.md) gives exact file bytes and hashes.

Use controlled inboxes if registration requires email confirmation. Never send fixture mail to documentation addresses. Record the actual confirmation setting.

The source enforces table and storage ownership through RLS. Record actual user, record, document and job UUIDs after populating the app.

The source's maintenance schedule archives completed reports older than 30 days. Keep the schedule paused. Preserve the schedule's actual command and timezone.

Export completed output when completed jobs exist. The observed source fixture has no completed job. Do not execute source jobs to change that fixture.

The additive `records.description` change can be tested after the source builder applies the change. An unbuilt requested field is not source data.

Keep the original framework and lockfile. Verify a server function, because a working static page cannot prove TanStack server hosting.

The destination in this example replaces the matching managed service calls. The [design](design.md) explains each source service and each replacement.
